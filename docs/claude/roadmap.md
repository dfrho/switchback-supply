## 2. Extra credit 1: observability plus a guarded rollout (highest value)

Story: Part 1's manual trigger is the first rung; a guarded rollout that watches metrics and rolls itself back is the top of the remediation ladder.

- Add `@launchdarkly/observability` and `@launchdarkly/session-replay` plugins through `ldOptions.plugins` in `createLDReactProvider`. Defaults are `privacySetting: 'strict'`. If a CSP is ever added, allow `pub.observability.app.launchdarkly.com` and `otel.observability.app.launchdarkly.com`. Docs: https://launchdarkly.com/docs/sdk/observability/react-web
- Autogenerated metrics include user error rate and web vitals; error rate is the recommended guardrail. Docs: https://launchdarkly.com/docs/home/metrics/autogen/observability
- Add a business metric too: `ldClient.track('add-to-cart')` (custom conversion binary) and order value as custom numeric. Event keys must match the metric exactly.
- Build a deliberate, demo-only fault in Express checkout behind a separate switch so a guarded rollout of `release-new-checkout` sees a real error-rate regression, plus a small traffic generator (Node, server SDK) so the rollout has enough sample. Rollbacks also happen for insufficient sample, which would muddy the story.
- Guarded rollouts need Guardian; the trial includes a limited number. Rehearse once and keep one in reserve. Docs: https://launchdarkly.com/docs/home/releases/guarded-rollouts and https://launchdarkly.com/docs/home/releases/managing-guarded-rollouts
- Demo payoff: rollout starts, errors spike, LaunchDarkly rolls back, session replay filtered by flag shows the failure.
- Done when: README section with persona framing, setup steps, doc links; tests for the tracking calls and fault switch; a rehearsed rollback.

## 3. Extra credit 2: AgentControl (AI Configs) shopping assistant on Anthropic

- "AI Configs" is now branded AgentControl (UI: Agents > Configs). Use Completion mode: a config `shopping-assistant` with variations by model and prompt, targeted by `loyaltyTier` so the Part 2 personas carry into the AI story.
- Server route (Vercel function under `api/`) using `@launchdarkly/node-server-sdk` (singleton) and `@launchdarkly/server-sdk-ai` (stable, maintenance mode; pin the version from the official Node guide). Call Anthropic with the config's model, parameters, and messages; map the system message correctly for Anthropic.
- The stable AI SDK has no Anthropic helper, so track manually with the tracker: duration, tokens, success or error, and thumbs feedback (`trackFeedback`). Mention in the README that the beta `@launchdarkly/ai-node` with `@launchdarkly/ai-claude-messages` automates this. Docs: https://launchdarkly.com/docs/sdk/ai/node-js-legacy and https://launchdarkly.com/docs/sdk/features/ai-metrics
- Fetch the config per request (reusing it across users breaks targeting). Provide a canned fallback when the config is disabled or the call fails.
- Keys: `LD_SDK_KEY` and `ANTHROPIC_API_KEY` in Vercel server env and `.env`, never `VITE_`.
- Done when: a chat panel in the store, a config change in LaunchDarkly changes the model or prompt live, Monitoring shows tokens, latency, and satisfaction, README section and tests (mock the Anthropic call).
